# حاضِر — نظام تحضير ذكي متعدد الجهات

نظام تسجيل حضور (SaaS) موجّه أساسًا **للمراكز الصيفية** (والمدارس والجامعات والشركات ومراكز
التدريب). كل جهة تُنشئ حسابًا مستقلًا تمامًا بعزل بيانات صارم، تضبط مواقعها وأوقاتها ونقاطها،
ثم تشارك **رابط تحضير عام** يسجّل المستفيدون حضورهم منه عبر جوالهم بالموقع الجغرافي والوقت.

> **المنتج مجاني بالكامل — بلا اشتراك ولا حدود ولا أي مسار دفع.**

### وضع المعاينة (بدون Supabase)
إن لم تُضبط مفاتيح Supabase، يعمل التطبيق تلقائيًا في **«وضع المعاينة»** ببيانات تجريبية محلية
(تُحفظ في `localStorage` داخل متصفحك). كل الشاشات والمنطق (التحضير، النقاط، التقارير، التصدير)
تعمل بالكامل. يوجد حساب تجريبي مهيّأ مسبقًا:

- **الجهة:** مركز طاقات الشباب · **رابط التحضير:** `/taqat-7f3a`
- **دخول لوحة التحكم:** `demo@hadir.app` / `demo1234`

## ربط Supabase (الإنتاج)

1. أنشئ مشروعًا على [supabase.com](https://supabase.com).
2. شغّل ملفات SQL بالترتيب من `supabase/migrations/` في **SQL Editor**:
   - `0001_schema.sql` — الجداول والفهارس والأنواع.
   - `0002_rls.sql` — تفعيل **RLS** على كل جدول + دالة `current_org_id()`.
   - `0003_public_functions.sql` — دوال عامة آمنة: `get_public_org` و`submit_attendance`.
3. انسخ `.env.example` إلى `.env` واملأ:
   ```env
   VITE_SUPABASE_URL=https://<ref>.supabase.co
   VITE_SUPABASE_ANON_KEY=<anon-public-key>
   ```
4. أعد التشغيل — سيتحوّل التطبيق تلقائيًا لاستخدام Supabase.

### كيف يُفرض العزل (Multi-Tenancy)
- كل صف بيانات يحمل `org_id`، والعزل مفروض على **مستوى قاعدة البيانات** عبر RLS لا الواجهة فقط.
- السياسة الموحّدة: `org_id = current_org_id()` حيث تُشتق `current_org_id()` من المستخدم الحالي
  (`auth.uid()`) عبر جدول `admins`. يستحيل تقنيًا لجهة قراءة/كتابة بيانات جهة أخرى حتى مع تعديل
  معرّفات الـ URL.
- `slug` عشوائي غير قابل للتخمين يُستخدم في الروابط العامة.
- القراءة العامة لصفحة التحضير تمرّ عبر دالة `get_public_org` (SECURITY DEFINER) التي تكشف
  **اسم الجهة + شعارها + نوافذ الوقت + المواقع المفعّلة فقط** — دون أي بيانات للمستفيدين.
- تسجيل الحضور يمرّ عبر `submit_attendance` التي تطبّق منطق الوقت/الجغرافيا/منع التكرار على الخادم.

## منطق الحضور

1. قراءة موقع الجهاز (Geolocation API).
2. التحقق أن الوقت ضمن نافذة مفتوحة وفق `time_windows` ومنطقة الجهة الزمنية؛ بعد `close_time` →
   `rejected (out_of_time)`.
3. إن كان `geo_required`: حساب المسافة (Haversine) لأقرب موقع مفعّل؛ إن تجاوزت `radius_m` →
   `rejected (out_of_range)` (تُسجَّل المحاولة وتظهر في التقارير مع المسافة).
4. عند النجاح: تحديد الحالة (مبكر/عادي/متأخر)، منح النقاط، إنشاء سجل، وعرض شاشة النجاح.

**الغياب:** المستفيد غائب إذا لم يسجّل في يوم نشاط معتمد (تُتجاهل العطل والأيام غير المجدولة).

## الأمان والخصوصية
عزل البيانات عبر RLS أولًا · تجزئة كلمات المرور (عبر Supabase Auth) · جلسات آمنة · منع التسجيل
المكرر (قيد فريد لكل مستفيد/يوم) · سجل تدقيق `audit_logs` لكل جهة. يُجمع أقل قدر من بيانات
المستفيدين (كثير منهم قُصّر): الاسم والمجموعة فقط.

> ملاحظة: المنتج جديد ولم يُطلق — لا تُعرض أي أرقام مستخدمين/جهات وهمية أو شهادات في الواجهة.
